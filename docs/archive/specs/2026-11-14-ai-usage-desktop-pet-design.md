# AI 用量桌宠设计

日期：2026-11-14。状态：**第一版已实现并完成本机隔离验收**。三端阶段提交、原始基线与数据库备份保留；实际进度以 PROGRESS.md 为准。

## 已确认需求

- 在 Mirror 网页中加入桌宠，桌面端显示；移动端暂不显示。
- 前八张参考图依次对应 DeepSeek、Gemini、Claude、GPT、Grok、GLM、Kimi、Qwen。第九张是统一画风参考。
- 全部重绘成极简 Q 版半身：大头圆脸、粗线条、扁平色块，保留各角色的发色、耳角和标志饰品。
- 默认跟随调用模型的厂商切换；允许手动固定角色；无法识别时使用第一只 DeepSeek。
- 除 Embedding 外，所有 AI 调用都统计。每次分析后提示本次用量，支持 Token、积分和未知三种结果。
- 点击有 Q 弹动作、表情变化与互动。需要能查看累计用量，并让桌宠本身有实用价值。
- 用户提供了本机 OpenAI 兼容测试入口和模型；凭据不进入代码、文档或日志。

## 方案比较与推荐

1. 浏览器临时统计：改动小，但覆盖不到后台总结、页面关闭期间的调用和可靠的历史累计。
2. **后端持久化用量，桌宠提供本次反馈与统计入口（推荐）**：覆盖前后台、刷新和多设备；增加统一采集与数据库迁移。
3. 独立的完整费用中心：适合预算、计价和财务报表，页面与维护成本更高，当前需求可由桌宠展开面板满足。

采用第二种作为本方案建议。先做可靠用量记录、角色互动和随手可查的统计，不引入价格表、人民币换算或额度扣款系统。

## 桌宠的实用价值

桌宠同时承担三个任务：提醒任务正在处理、解释刚才的用量、提供累计用量入口。

- 分析中切到认真表情；并行任务显示“正在处理 2 项”，不伪造完成进度。
- 完成后弹简短气泡，例如“随记整理完成，本次 1,240 Token”。按一个完整业务任务汇总，展开可查看内部请求。
- 混合或不完整结果写成“已知 860 Token，另有用量未知的请求”；用户可以看见统计缺口。
- 气泡点击进入该次任务明细；悬停或键盘聚焦出现“用量 / 换角色 / 收起”三个操作。
- “用量”打开附着在角色旁的面板，默认显示今天；可切本月、累计和日期范围，按模型、功能筛选。
- 角色操作区同时提供“账本 / 模型设置”快捷路由；使用现有路由入口和导航草稿确认，不能绕过未保存内容保护。
- 面板显示任务数、请求数、已知 Token、各渠道积分、未知次数。积分按渠道分别累计；不同平台的积分不做一个混合总数。
- 点角色本体只触发表情和弹性互动，避免为了摸一下角色被迫打开面板。
- 模型中心增加“AI 用量 / 显示桌宠”入口，复用同一桌面面板，便于桌宠收起后找回。

示意数据仅用于说明布局，不是当前账号真实用量：

### 行为

- 默认右下角，留出边距，避免与回顶、成就通知、聊天输入区重叠；弹出窗口时临时避让。
- 可拖动，限制在可见视口内；松手小幅回弹；拖动不会误触点击互动。位置按账号保存在本机。
- 点击依次或随机触发害羞、鼓脸、开心等表情，配合短暂挤压、拉伸和回弹。连续点击有节流，动画可中断，不无限叠加。
- 待机偶尔眨眼，长时间无操作进入休息；开始任务立即恢复；不自行在页面上游走。
- 气泡默认约 6 秒后收起；悬停暂停；并发完成合并或排队，已读结果不因切页、刷新或多标签页重复刷屏。
- 页面重新打开时直接更新累计与最近记录，不把离线期间的全部历史任务逐条弹出来。
- 外观选择有“跟随模型”和八个角色。手动选择一直保持，直到用户重新选择跟随。
- 自动模式优先识别实际返回的模型名，其次请求模型名，再使用明确的厂商配置；OpenAI 兼容协议本身不代表 GPT。识别别名包括 Gemini/GPT/OpenAI/Grok/GLM/Zhipu/Kimi/Moonshot/Qwen/Claude/Anthropic/DeepSeek。
- 自定义代理的 `cn:deepseek-v4.1-flash` 应识别为 DeepSeek。未知模型回退 DeepSeek；Gemini/Grok 素材不意味着新增原生调用协议。
- 多任务时前台任务优先，后台结果不抢正在处理的角色；模型切换不能覆盖用户手动选择。
- 桌宠只在桌面布局且实际视口达到桌面阈值时挂载，窗口变窄立即移除。不能因手机强制选择桌面模式而显示桌宠。移动端调用仍正常计入后台统计。
- 支持键盘操作、清楚的焦点、减少动态效果偏好；默认无声音；点击互动全部在本地完成，不新增 AI 请求。

## 统计口径

### 覆盖范围与颗粒度

覆盖 legacy、graph_v2、shadow 的实际 LLM 请求，以及记录拆分/分类、词典抽取、对话规划/回答、聊天记忆、每日/对话总结、镜子画像、塔罗、凭证识别、模型连接测试。影子请求标记“影子验证”。不计 Embedding、只读工具、数据库查询和纯本地互动。

一个用户操作或定时任务是一个 task；内部每次真正发往上游的请求是一个 attempt。同一任务的多次规划、重试和回答都可追溯，任务汇总只加实际请求回执，不再加一次任务总数，避免双算。后续独立定时任务有自己的任务归属和入口说明。

自动重试也需观察到每次网络尝试，不能只在业务方法返回时记录最后一次。重试策略和既有调用预算保持现有行为，采集逻辑不得为获取用量重发请求。

请求数指观察到的上游尝试，不等于计费成功次数。RPC 明确报告未发起上游请求时不计一次 AI 请求或消费，明细可说明“本次未调用模型”。用量缺失的已确认尝试与未收到报告的 invocation 分别计数，后者显示“统计不完整”，不伪造其物理请求数量。

### Token、积分、未知

- Token 取上游 usage，支持输入、输出、总数；缓存、思考等细分按协议规则规范化，不重复加进总数。仅有总数时，输入/输出保持未知。
- OpenAI 兼容流读取末尾 usage，包括 `choices=[]` 的统计块；中断没拿到完整统计时不补造零值。
- Anthropic 流合并起始和最终 usage；累计计数取最终值，不把每次累计值相加；缓存读写按该协议的输入计数定义处理。
- 积分只识别含义明确的“本次消耗”字段；额度百分比、余额、重置时间等不当作消费。接口特定字段有独立适配器与契约测试，没有契约则保持未知。
- 两种用量同时可确认时均保存，主气泡优先 Token，明细可列积分；只有积分时显示积分；都没有时显示“接口未返回可识别用量”。
- 正常响应、失败、取消都保留执行状态与已知用量。失败不等于免费；缺失用量不等于 0。部分已知时显示“已知合计 + 未知次数”。
- 只有接口明确返回且语义确认的 0 才是已知零。没有推断人民币或站内成长积分的换算。
- 积分按用户、模型档案、计费入口/渠道及单位分组；模型厂商和计费渠道分开。模型配置后续修改不能重写历史归属。
- 积分用十进制定点保存与加总，禁止用浮点数累计；非法、非有限和不能确认语义的数值不参与合计。Token 总数采用后端整数精确计算，前端只格式化显示。
- 时间按 Asia/Shanghai 的自然日和自然月；累计从该功能启用开始。历史日志不回填成估算值。

### 已完成的一次接口探测

2026-11-14 使用用户授权的本机测试模型作极小非流式请求，实际返回：输入 34、输出 16、总数 50 Token，同时有 `usage.credit=0` 与 `usage.quota.percent=17`。这个样例确认 Token 回传可用；不能据此认定积分为零代表免费，也不能把额度百分比换算成积分。该探测没有写入业务账号用量；正式实现仍须验证流式场景和任务归集。

## 三端职责与传输边界

### AI

- 在共用的 LLM/SDK 边界观察物理请求，覆盖 OpenAI 与 Anthropic 的同步、流式、JSON 规划和工具规划，保留既有返回文本接口。
- gRPC 入口创建请求级采集上下文；线程/任务切换时显式传递，禁止进程全局“当前用户/用量”。Embedding 路径不创建统计。
- 只保留数值、状态、请求 ID、模型/协议等白名单字段，不记录原文、回答、图片或密钥。Python 不连业务库、不保存持久会话。
- 正常、异常与流结束时形成版本化用量报告，用 gRPC 二进制 trailers 回传。第一版采用有界 UTF-8 JSON 载荷，避免为所有业务 response 增字段；契约写入实施计划和协议登记，Java/AI 共享测试样例。

### Java

- Java 在每个非 Embedding RPC 发起前绑定可信 owner、task、invocation、场景及模型档案快照；普通客户端不能上报或修改消费值。
- 同时覆盖 `AiGrpcClient`、`TarotGrpcClient`、`AgentGrpcClient`，异步和定时任务不能依赖 HTTP 线程的登录上下文。
- RPC 发起时持久化 invocation 的待完成状态；统一 client interceptor 在成功/失败结束时接收报告。按 invocation + attempt ID 幂等写入；业务事务失败不会回滚已产生的调用用量。
- trailers 有大小/数量上限且必须验证；超限、网络中断、取消或旧版 AI 未报告时，将该 invocation 标为未完整报告，不造出“1 次物理请求”或虚假的 Token。请求数展示已确认次数并标未报告请求。
- 上游物理请求数量在网络故障时可能无法确认；统计保留这个边界，已知合计只是下界。不得声称能恢复未收到的账单。
- 统计记录、任务归集与查询由 Java 完成；新表使用下一编号迁移（当前预计 V21，实施时再确认），同提交更新 `schema.sql`、协议登记、API 文档与测试。
- 用量持久化失败不能使成功的 AI 业务结果失败；待完成状态和独立统计事务/有界补偿用于暴露缺失，不能静默丢失或无限重试。
- 新增当前用户的聚合、分页记录和任务明细只读接口，所有查询按认证身份过滤；配置删除后仍能读历史的脱敏模型快照。

### 前端

- 在登录后的公共布局挂载独立桌宠组件与用量 store，不侵入各业务页面重做计费逻辑。
- 完成事件触发刷新，辅以可见页面的轻量增量轮询，覆盖后台任务；隐藏页面暂停轮询，恢复时取服务器最新状态。
- 服务器汇总是累计真源；前端不靠收到几次通知就给总数加几次。按账号清理缓存、游标和偏好，避免串号。
- 分析状态来自任务状态而非定时猜测。耗时很长的后台任务保留场景名称；前台与后台结果的气泡可区分。
- 首屏不弹旧账、重复回放不重算；跨日、刷新、多标签页、配置切换后的累计保持一致。

## 验收与交付边界

1. 八个透明半身角色及八类表情齐全，与原图身份和第九张画风一致；实际页面截图证明可辨识和切帧无跳位。
2. 自动/手动/未知回退、代理模型别名、同时多任务、拖拽回弹、点击不误开面板可验证。
3. 真实本机测试模型验证同步和流式 Token、至少一个业务任务多请求归集；积分与未知分支用明确夹具验证，不能冒称已验证真实积分平台。
4. 除 Embedding 外覆盖所有上述入口，含后台任务、连接测试、重试、错误和取消；未知和部分回执可见。
5. 今日/本月/累计按服务端归集，多渠道积分分开，缓存/思考不重加；幂等、多标签页和不同用户隔离通过。
6. 桌面截图覆盖气泡、统计、换角色、弹窗避让；手机和窄屏没有桌宠 DOM，移动调用仍计入统计。
7. 在隔离数据库验证新迁移与 fresh schema；不把本机隔离库验证描述为另一台机器或生产已升级。
8. 更新 B `PROGRESS.md` / `REFERENCE.md` / `shared-protocol.md`、AI 协议/启动说明及 `upload/` 同步、F 交互说明与测试；设计完成后按仓库规则归档并更新索引。

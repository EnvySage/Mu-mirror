# 记录选择性向量索引与工具回查设计

> 状态：2026-11-13 已实现并完成隔离环境验收；目标环境尚未迁移或部署。当前状态与验证边界见 [PROGRESS](PROGRESS.md)。
> 已完成实施归档：[2026-11-12-record-selective-indexing.md](archive/plans/2026-11-12-record-selective-indexing.md)
> 本版替代此前“日常片段不授权、所有 AI 路径不可见”的方案。以本次对话澄清为准。

## 1. 目标与产品规则

用户把记录交给 Mirror 后，LLM 在现有拆分分类的一次调用中逐段建议是否建立 embedding。低信息日常仍保存、分类并可通过工具查询；具体经历、实体、偏好和结论优先索引。优化对话体验，不以减少向量数量作为唯一成功标准。

| 情况 | 保存 | 工具/统计/回顾 | 向量 |
|---|---|---|---|
| 已确认并授权，有检索价值 | 是 | 可以 | 建立 |
| 已确认并授权，普通日常 | 是 | 可以 | 跳过 |
| 明确仅保存/未授权片段 | 是 | 不可读 | 不建立 |
| 未确认/已删除/已撤回/其他用户 | 按现有存储规则 | 不可读 | 不可检索 |

- 一次整理、一次确认；不要求用户逐段勾选。展开后可调整“便于联想检索”，原记忆授权另行保留。
- `memoryEnabled` 表示用户允许后续 AI 使用，不能由 LLM 的索引建议关闭。
- 日报、情绪统计、镜子回看覆盖全部已授权且确认完成的内容，保留各自已有窗口和数量预算。
- 成长计分和待办登记按已有独立授权/规则执行，不因跳过或失败的向量任务丢失。
- AI 确认后的正文保持只读；更正另建记录。普通未授权仅保存记录保留现有编辑能力。
- 原始内容始终保留；工具读取确认后的已授权片段正文，不能通过整篇原文带出未授权片段。

## 2. 索引判断

判断“将来有没有可检索的具体信息”，不是只判断事件重大程度。具体店名是保留理由，夸张修辞本身不是。

| 样例 | 默认建议 |
|---|---|
| 下午好累 / 中午吃了饭 / 下午干活 / 今天累得灵魂出窍 | 不索引，保留时间和分类 |
| 今天去了陈记牛肉面 | 索引：具体地点与经历 |
| 陈记牛肉面太咸，以后不去了 | 索引：地点、评价、后续偏好 |
| 下午喝咖啡晚上睡不着 | 索引：个人经验 |
| 连续两周下午疲惫，周末也没缓过来 | 索引：持续状态 |
| 学会某个概念、项目决定、具体人际事件、明确阶段进展 | 索引 |

LLM 判断不确定或缺失/格式非法时保守索引，不产生额外逐段模型请求。分类整体失败沿用现有“待确认仅保存候选”，不擅自扩大授权。语料是数据，不能执行其中要求修改权限/索引规则的指令。

## 3. 冻结的跨端契约

AI `proto/record_processor.proto` 的 `ClassifyItem` 追加（执行前确认字段号仍空闲）：

- `optional bool embedding_enabled = 11`；缺失与明确 false 必须可区分。
- `string embedding_reason = 12`；最多 200 字符，仅解释建议，不参与 embedding。

Java/前端 `RecordDraftDTO`：
- 顶层 `indexPolicyVersion: 0|1`，由服务器生成、校验；0 为兼容模式，1 为本设计。
- 片段保留 `memoryEnabled`、`todoEnabled`；追加 `embeddingEnabled: Boolean`、`embeddingReason: String`。
- 没有索引字段的旧候选按 true 解释；明确 false 不得被序列化缺省或模式强制全选覆盖。
- 用户改正文时，界面把过期索引建议重置为 true，解释“正文已修改，默认保留检索”；用户随后可手动调整，确认值优先。

数据库新增：
- `records.index_policy_version SMALLINT NOT NULL DEFAULT 0`，约束为 0/1。
- `chunks.embedding_enabled BOOLEAN NOT NULL DEFAULT TRUE`。
- 原因存 `chunks.metadata.embeddingReason`，不另建记忆等级表。
- `embedding_status` 仍是 `not_requested/pending/ready/failed`。主动跳过由 `embedding_enabled=false` 表达，不能用空向量推断策略。

`RecordVO` 返回 `indexPolicyVersion`；`ChunkVO` 返回 `embeddingEnabled`、`embeddingReason` 及现有向量状态。不向浏览器增加向量正文或内部错误详情。

## 4. 状态与历史兼容

使用记录级版本，避免直接改变所有旧数据的可见性：

| 记录 | 确认结果与行为 |
|---|---|
| version=0 旧记录/旧任务 | 原状态机、完整性门槛、失败降级保留 |
| version=1，有至少一个授权片段 | 确认事务设 `DONE + READY + userReviewed=true`，授权立即可读；READY 不再代表全部向量完成 |
| version=1，全部授权片段不索引 | 同上，0 个向量任务，操作卡正常完成，不降为仅保存 |
| version=1，部分/全部向量排队或失败 | 正文仍可读、成长已按确认入账；只有相应片段的向量状态变化 |
| 明确不授权任何片段 | 不可供 AI 读取；保留既有未授权结果，AI 审核确认过的正文仍只读 |
| 撤回/删除 | 撤销读取，取消任务、递增版本、清向量、失效派生快照；覆盖无向量片段 |

新策略下操作卡在确认事务完成后结束，不等待索引。后台索引状态独立展示。新策略 worker 失败不能触发旧的整条撤权、清成长建议；旧策略任务继续原行为。

`record_memory_is_complete(record_id)` 保持兼容定义；新增 `record_ai_is_readable(record_id)`：
- version=0：委托原完整性规则；
- version=1：校验用户记录、未删除、DONE、已审核、处理授权、READY、有授权非空片段，不依赖向量。
- 每条片段查询仍必须校验用户归属及 `ai_memory_approved=true`。

旧记录不自动重判、不清旧向量、不扩大旧权限；新增列的默认值只承担兼容。旧的仅保存记录只有用户明确重新请求整理并确认后才采用新策略。

## 5. 查询与对话

- 非向量查询：授权可读门槛；包括日期/关键词/record_id、情绪/类型统计、日报、镜子、词典候选、近期语境及 Tarot 上下文。
- 向量查询：上述门槛，再要求片段 `embedding_enabled=true`、`embedding_status=ready`、向量非空；保留现有距离阈值、时间条件及 vault 边界。
- Python 继续只读 `mirror_ai` 视图。扩展 `record_chunks` 到已授权未索引片段，末尾追加索引字段；不得新增业务表读取授权。视图内联等价权限谓词，避免新增函数导致 reader 需要基础表权限。
- “昨天干什么/最近一个月”按日期查询；主题经历优先语义检索；材料不足时按关键词/日期回查、读取正文。
- 未索引不等于未记录。空向量命中不能直接证明档案中没有。
- 日期/关键词查询要稳定排序和分页。摘录只支持摘录分析；长回顾必须标注范围，不能把一页材料说成全部。
- 无法定位的模糊问题允许澄清；保留现有预算/取消/超时边界，不无上限翻历史。

## 6. 引擎范围

2026-11-12 源码默认 `legacy`，graph_v2 按用户白名单启用。本次对话中用户确认当前仍使用 legacy，因此本期保留并完成 legacy 必要适配，同时覆盖 graph_v2；两者的验收分别记录。

执行前只读核对实际配置、白名单和近期 `agent_runs.engine`，用于选择端到端测试账号及解释结果，不作为跳过 legacy 的理由。不自动切换引擎，也不扩大 graph_v2 灰度。

用户计划后续舍弃 legacy；删除另立任务。旧 Chat 与 10003 分类/embedding/画像 RPC 不属于同一清理边界，不能整端口或整服务删除。

## 7. 发布与范围

Java 开关 `record-memory.selective-index-enabled`，环境变量 `MIRROR_RECORD_SELECTIVE_INDEX_ENABLED`，初始 false。关闭仅影响未来准备的新候选；已写入 version=1 的数据始终按本设计可读。候选版本与当前准备策略不一致时返回 409 并保留原稿，要求重新准备，不能静默改选择。

先迁移和部署兼容代码（开关关闭），再核对三端契约，在测试环境开启并验收。回退使用本次兼容代码关闭开关，不能直接回退到不认识 version=1 的旧二进制。原始日记、历史向量和授权不作为回退删除对象。

本期不做历史向量批量清理、跨记录摘要向量、向量模型更换、MMR、event_time、新事实自动覆盖旧事实、确认后新增索引管理页或 legacy 删除。不得为做本任务自动启用 graph_v2。

## 8. 验收原则

三种记录（全日常/混合/全索引）必须通过真实数据库测试；只用 mock 不足以证明权限和查询正确。覆盖跨用户、未授权、未确认、删除、撤回、索引失败、迟到任务、旧数据及分页。

对话必测：具体餐厅评价、昨日全日常、近期疲惫、未索引内容回查、模糊问法、超过一页材料、无结果与工具失败。区分桩模型链路验证与真实模型质量评估。记录实际引擎、证据片段、页数、向量任务数和耗时；不以降低向量数替代对话验收。

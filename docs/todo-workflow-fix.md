# 待办与记录审核衔接修复

原问题：RecordActionHandler 确认记录时始终传入空的 todoChunkIds；单段 Classify 未注入 open_todos，且没有将 refers_to_todo 转为可审核的候选；前端完成后没有刷新侧栏实际使用的证据链。

修复：AI 生成待办候选时提供独立 todoEnabled 开关，在完整编辑台明确展示、允许取消；手动改为待办时默认勾选。确认后按选择登记。旧候选没有该字段时保持 false，避免追溯推断用户授权。记忆授权和待办授权仍分别落库。

单段整理现在传入按用户隔离的已有未完成待办；模型引用必须匹配本人未删除的真实任务。候选 todoSuggestions 只用于展示，不直接改任务。用户采纳后，或通过手动选择已有任务，才将 todoResolutions 随确认提交，复用已有事务内的状态更新和 evidence link 逻辑。关联已有任务时默认关闭新建待办，避免重复登记。

前端确认返回和后台完成时均刷新 todo 的建议、登记表和证据链；常驻轮询也会刷新证据链。

本地使用隔离测试库、可控模型桩与真实浏览器验证：新任务出现、AI 关联提议经确认后追加进度且不重复建任务、手动关联后完成并从 OPEN TODO 移除，全部通过。模型关联的实际准确率仍取决于用户配置的模型。

本补丁没有新表或结构迁移，也不批量修改历史记录的 todoApproved 标志；历史遗漏必须先核对或由用户明确确认。

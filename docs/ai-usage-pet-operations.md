# AI 用量与桌宠运维

当前实现及验收状态以 [PROGRESS.md](PROGRESS.md) 为准。API 字段与筛选定义见 [REFERENCE.md](REFERENCE.md)，gRPC 元数据契约见 [shared-protocol.md](shared-protocol.md)。

## 职责与口径

Python 在请求级上下文中观察上游 LLM 网络尝试，包含 SDK 重试；Java 绑定可信账号、场景和模型档案，保存回执并计算汇总；前端桌宠提供通知、统计和快捷入口。Embedding、数据库查询及本地表情互动不计入。

- 一个业务操作可以包含多次请求；总数从唯一请求回执计算，不把任务汇总再加一次。
- Token 和各渠道积分分开。积分用十进制定点处理，渠道和单位不同则分别列出。
- 完整总数优先使用接口明确返回的 total；只有部分输入/输出已知时，展示其可确认下界并保留未知提示。缓存和思考细分不再重复加到总数。
- 接口未返回或网络未送达的用量显示未知/统计不完整。失败和取消也可能产生用量。
- 积分只接收语义明确的本次消耗字段；额度百分比、余额或含义不明的 credit 字段不能当成扣费。增加渠道适配时先补响应契约与回归。
- 今日、本月和日期范围按 Asia/Shanghai；累计从功能启用开始，不从旧日志估算补账。
- 回执与业务事务独立，业务保存失败也保留已经发生的调用用量。统计完成只表示用量可查看，不等于业务保存成功。

## 桌面入口

登录后的桌面布局显示桌宠；窄屏和无桌面指针能力的触屏设备不挂载桌宠，后台统计仍照常执行。

点角色触发本地表情，拖动调整位置；操作区可查看用量、换角色、收起，或跳转现有 `/ledger` 与 `/models`。模型中心提供恢复入口。快捷路由经过既有草稿保护，AI 用量记录不自动写入个人收支账本。

角色默认按实际/请求模型与明确的厂商信息识别；手动固定优先；未知使用 DeepSeek。八角色依次为 DeepSeek、Gemini、Claude、GPT、Grok、GLM、Kimi、Qwen。外观 ID 与 API 厂商 ID 分开，Claude/GPT/GLM/Kimi 的筛选分别使用 anthropic/openai/zhipu/moonshot。

素材清单与维护见前端 [pet-assets.md](../../Mu-mirror-F/docs/pet-assets.md)。仅加载项目内透明图集，不在访问网页时生图；气泡和点击不会为生成台词额外调用模型。

## 升级

三端使用同一批功能版本。Python 旧版或统计回执缺失时，Java 保留调用包络并标记不完整，不能以 0 代替。

1. 备份目标数据库。已有库先按既有版本路径升级到 V20，再执行 `src/main/resources/db/migration-v21-ai-usage.sql`；新库使用包含 V21 的 `schema.sql`。
2. 使用 `psql -X -v ON_ERROR_STOP=1 -1 -f ...` 执行迁移。V21 只增加用量任务、调用包络和请求回执结构；两台机器各自执行并记录结果。
3. 启动匹配的 AI 与 Java，再启动前端；本机地址和连接差异仍放本地覆盖或进程参数，不修改共享默认配置。
4. 用独立验收账号执行模型测试、同步和流式任务，核对回执、汇总、气泡和不同账号隔离。真实积分渠道未提供时，应明确积分分支是契约夹具验证。

正常 gRPC 报告有数量和大小上限；服务器中断、取消或超限时保留已知前缀并显示统计缺口。服务端日志只记录调用 ID 和失败类别，不输出模型输入、回答、图片或密钥。

## 回退

先保存当前功能版本和验收证据，再将三端一起切回已记录的基线，重启对应服务。新增统计表可保留，旧代码不依赖它们；不需要为代码回退删除用量记录。

若确需核对迁移前数据，应把备份恢复到新的隔离数据库后比较，避免覆盖现有库。本机测试迁移和验收不代表另一台机器或生产已升级。
